뭐샀지 구매 기록 공통 CSV v1
작성 기준: 2026-10-12

사용 방법
1. 빈 양식을 복사해 사용합니다. 첫 줄은 열 이름이고, 두 번째 줄부터 구매 기록을 적습니다.
2. 열 이름과 순서를 그대로 유지합니다. 한 레코드는 한 번 구매한 한 품목입니다.
3. 예시 파일의 다섯 기록은 모두 가상 데이터입니다. 실제 기록과 섞지 마세요.
4. 저장 형식은 CSV UTF-8(쉼표로 분리)입니다. 이 양식에는 한글 호환을 위한 BOM이 들어 있습니다.

고정 헤더
date,name,category,price,quantity,shop,cycleDays,note

열별 작성 기준
date — 구매일 / 필수
  YYYY-MM-DD, 예: 2026-10-01. 실제 달력 날짜이며 1900-01-01부터 오늘까지.
  엑셀에서 편집할 때 날짜 표시 형식을 yyyy-mm-dd로 맞춥니다.
name — 상품명 / 필수
  1~120자. 예: 고양이 간식. 같은 상품은 이름을 일정하게 적으면 재구매 기록을 묶기 쉽습니다.
category — 분류 코드 / 필수
  cat=고양이, dog=강아지, clothes=옷, life=생활, other=기타.
  이 다섯 영문 소문자 코드 중 하나만 적습니다. 한국어 분류명은 설명용입니다.
price — 해당 품목의 총 구매 금액(원) / 필수
  0~1000000000 사이의 정수. 예: 3봉을 총 18000원에 샀으면 18000.
  개당 가격이 아니며 수량을 다시 곱하지 않습니다. 쉼표, 원, ₩, 소수점은 넣지 않습니다.
  금액을 모르면 0. 현재 앱에서 0은 '금액 미입력'으로 표시되어 무료 구매와 구별되지 않습니다.
quantity — 수량 / 선택
  최대 40자. 예: 3봉, 1벌, 1팩 (30롤). 빈칸의 기본값은 1개입니다.
shop — 구매처 / 선택
  최대 120자. 모르면 빈칸으로 둡니다.
cycleDays — 재구매 주기(일) / 필수
  0~3650 사이의 정수. 예: 30. 알림이 필요 없으면 0.
  월 단위가 아닌 일수이며, 기본 재구매 예정일은 구매일에 이 일수를 더한 날짜입니다.
note — 메모 / 선택
  최대 2000자. 모르면 빈칸으로 둡니다.

CSV 저장 규칙
- UTF-8 BOM, 쉼표(,) 구분, CRLF 줄바꿈을 사용합니다.
- 모든 레코드는 8개 필드를 유지합니다. 빈칸을 나타내는 쉼표도 생략하지 않습니다.
- 쉼표·큰따옴표·줄바꿈이 포함된 필드는 큰따옴표로 감싸고 내부 큰따옴표는 두 번 적습니다.
  예: 메모가 정기구매 후보, "참치맛" 선호이면 CSV에는 "정기구매 후보, ""참치맛"" 선호"로 저장합니다.
- 첫 줄 앞에 제목·설명·sep= 문구를 넣지 않습니다. 합계 행이나 수식도 넣지 않습니다.
- 수입·환불·음수 금액은 이 구매 기록 v1 규격에 포함하지 않습니다.

앱·파이썬 연결 기준
- 열 이름은 현재 앱의 구매 기록 필드와 같습니다.
- 읽을 때 UTF-8 BOM을 제거합니다. 파이썬은 encoding='utf-8-sig', newline=''으로 파일을 열고 csv.DictReader를 사용합니다.
- 필수 필드가 비거나 잘못된 날짜·분류·정수가 있으면 저장 전에 해당 레코드를 확인합니다.
- price와 cycleDays는 정수로 변환합니다. quantity 빈칸은 1개, shop과 note 빈칸은 빈 문자열로 처리합니다.
- id와 createdAt은 앱에서 생성하므로 양식에 넣지 않습니다. 알림 미루기 상태 등도 CSV에는 포함하지 않습니다.
- 현재 앱의 가져오기는 JSON 백업용입니다. 이 CSV를 앱에 직접 가져오는 기능은 아직 연결되지 않았습니다.
- 이 양식은 전체 백업이 아닙니다. 앱 복원에는 기존 JSON 백업을 사용합니다.

보관
CSV는 암호화되지 않은 일반 텍스트입니다. 개인 구매 내역을 적은 파일은 본인 휴대폰·PC에 보관하세요.
파일 생성 과정에서 실제 구매 기록을 읽거나 외부로 업로드하지 않았습니다.
